## Explanations (by question)

1. **B** — Requirements Management is ongoing and touches every ADM phase; it is not confined to a single phase.  
2. **A** — Preliminary sets up the **enterprise** to do EA: governance, capability, principles, frameworks.  
3. **C** — Phase A establishes vision, stakeholders, scope, and agreement to proceed — not detailed modeling or Phase G contracts.  
4. **A** — Phase B is the **Business Architecture** domain.  
5. **D** — Phase C is **Information Systems**: **Data** + **Applications** (not Technology — that is D).  
6. **D** — Phase D develops **Technology Architecture** (baseline/target, standards).  
7. **D** — Phase E groups gaps into **work packages** and solution chunks; roadmap timing is Phase F.  
8. **D** — Phase F is **Migration Planning** (roadmap, sequencing, transition).  
9. **C** — Phase G **governs implementation** and **conformance** (contracts, compliance).  
10. **D** — Phase H manages **change** to the architecture and monitors drivers after delivery.  
11. **D** — **Viewpoint** = conventions/specification for a class of views (the “recipe”).  
12. **A** — **View** = actual representation addressing stakeholder **concerns**.  
13. **C** — **Concern** = stakeholder **interest** the architecture should address.  
14. **D** — **ABB** = logical architecture building block (capability/behavior at architecture level).  
15. **B** — **SBB** **implements** an ABB (real product/component).  
16. **D** — Enterprise Continuum classifies assets from **generic** toward **organization-specific**.  
17. **D** — Organization-Specific Architectures are the most tailored end of the Architecture Continuum.  
18. **D** — **Reference Library** holds reference models, patterns, templates, guidelines.  
19. **B** — **Standards Information Base** holds standards (including mandatory org standards).  
20. **B** — **Governance Log** records governance decisions and compliance outcomes.  
21. **B** — **Architecture Capability** defines roles, skills, organization to run EA (not the landscape itself).  
22. **A** — **Architecture Landscape** holds states at strategic / segment / capability / operational levels.  
23. **B** — Principles **constrain** and **guide** decisions from strategy.  
24. **B** — Architecture Board = **governance** and **decisions** on architecture direction and compliance.  
25. **B** — **Architecture contracts** are a Phase **G** mechanism between governance and delivery.  
26. **B** — Compliance assessments measure **conformance** to the architecture.  
27. **A** — Business scenarios frame the **problem**, stakeholders, and concerns for scoping.  
28. **B** — Iteration allows **feedback** — later phases refine earlier results.  
29. **A** — Gap analysis compares **baseline** vs **target** to find gaps.  
30. **C** — Architecture Development Cycle supports **structured, governed** evolution of architecture.  
31. **B** — **Preliminary** establishes **EA capability** and governance **for doing EA**; Phase A is initiative-specific vision.  
32. **A** — Phase A yields **Architecture Vision** and approval to proceed.  
33. **B** — **Data Architecture** sits in Phase **C** (with Applications).  
34. **B** — **Applications Architecture** is Phase **C**.  
35. **C** — **Technology Architecture** is Phase **D** (option order places D in C).  
36. **A** — E = **what** to deliver/group; F = **when/how** to migrate (roadmap).  
37. **B** — G = **implementation governance**; F = **migration planning** (do not swap).  
38. **D** — Phase H = **change management** for the architecture lifecycle post-go-live and new drivers.  
39. **D** — Content Metamodel structures **architecture content** and relationships — not a replacement for ADM.  
40. **D** — On “PRIMARY” / “BEST” questions, pick the answer that matches **TOGAF intent**, not informal habit.
