# Phase C — Information Systems Architectures

**Purpose:** Develop **Information Systems Architectures** = **Data Architecture** + **Applications Architecture**.

## Key terms

| Term | Short description |
|------|-------------------|
| **Data Architecture** | Structure and meaning of **information assets**, relationships, and data-related constraints. |
| **Applications Architecture** | **Logical** structure of applications that support the business (not yet full tech stack — that is D). |
| **Information Systems (IS)** | In TOGAF exam usage, IS architectures = **Data** + **Application** domains together in Phase C. |
| **Gap analysis** | Baseline vs target for **data** and **applications**. |

## Functions (exam level)

- Define how **information** and **applications** realize Business Architecture.
- Produce IS-level baseline, target, and gaps.

## Links to other phases

- **From Phase B:** Business needs and constraints drive data and application design.
- **To Phase D:** Data and application outcomes drive **technology** choices and standards.
- **Requirements Management:** IS-level requirements flow through the hub.

## Boundaries

- **Not Phase B:** Business-only modeling as the **main** deliverable belongs in **B**.
- **Not Phase D:** **Technology** architecture (platforms, tech standards mapping) is **D**, not the main focus of C.
