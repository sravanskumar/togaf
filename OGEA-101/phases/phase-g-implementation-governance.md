# Phase G — Implementation Governance

**Purpose:** **Govern** solution development so delivery **conforms** to the architecture — **contracts** and **compliance**.

## Key terms

| Term | Short description |
|------|-------------------|
| **Architecture contract** | Agreement between **governance** and **delivery** on scope, conformance, and acceptance criteria. |
| **Compliance assessment** | Activity to **measure** how well an implementation (or supplier) **matches** the architecture. |
| **Conformance** | Alignment of projects/products with the **agreed** architecture. |

## Functions (exam level)

- Ensure projects implement the **target architecture** (or documented exceptions).
- Manage **waivers** and escalations through **governance** (e.g. Architecture Board context).

## Links to other phases

- **From Phase F (and earlier):** Implements what was **architected** and **planned** to migrate.
- **To Phase H:** Discoveries and changes during/after implementation feed **architecture change management**.
- **Requirements Management:** Implementation issues and changes update requirements.

## Boundaries

- **Not Phase F:** G does **not** own the **migration roadmap** as its primary output — that is **F**.
- **Not Phase H:** G is **during-build** (or program) **governance**; H is **ongoing** evolution of the architecture after environmental change.
