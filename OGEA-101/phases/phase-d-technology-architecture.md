# Phase D — Technology Architecture

**Purpose:** Develop **Technology Architecture** — technology **baseline** and **target** and alignment to **standards**.

## Key terms

| Term | Short description |
|------|-------------------|
| **Technology baseline** | Current **platforms**, infrastructure, and technology environment. |
| **Technology target** | Desired **tech** landscape that supports applications and data. |
| **Standards mapping** | How the target technology conforms to **organizational** and external **standards**. |
| **Gap analysis** | Technology baseline vs target gaps. |

## Functions (exam level)

- Complete the architecture stack under B/C with **technology** decisions and patterns.
- Make implementation and migration planning **technically** grounded.

## Links to other phases

- **From Phase C (and B indirectly):** Application and data needs drive technology direction.
- **To Phase E:** Full B/C/D picture supports **solution grouping** and **work packages**.
- **Requirements Management:** Technical constraints and requirements are maintained centrally.

## Boundaries

- **Not Phase E/F:** Does **not** primarily define **work package** groupings (E) or **migration roadmap** timing (F).
- **Not Phase G:** Does **not** run **project conformance** — that is implementation governance.
